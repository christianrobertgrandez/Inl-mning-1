### Sammanfattning

Det jag har märkt hittills är att vissa delar tog mer tid än jag först tänkte. Det var inte själva texten i HTML som var svårast, utan mer att fundera på vilka taggar som passade bäst och hur sidan skulle byggas upp på ett bra sätt.

När allt är klart kan jag jämföra bättre med mina första estimat och se vad jag skulle uppskatta annorlunda nästa gång.


## Struktur

Jag har försökt använda semantiska taggar där det känns naturligt, till exempel `header`, `nav`, `main`, `article`, `section` och `footer`.

Jag har också tänkt på ordningen på innehållet. Även utan CSS ska sidan gå att läsa uppifrån och ner på ett logiskt sätt. Senare går det att ändra layouten med CSS utan att behöva göra om hela HTML-koden.


## Tillgänglighet

Jag använde AI för att få hjälp att granska tillgängligheten i koden.

Jag kollade bland annat rubrikordningen, alt-texter på bilder, labels till formulärfält och de semantiska taggarna.

Efter granskningen ändrade jag några saker, bland annat vissa alt-texter och delar av strukturen.

Jag ska också kontrollera sidan i webbläsarens utvecklarverktyg och se om den kontrollen visar något annat än AI-granskningen.


## Bara HTML

Sidan innehåller ingen CSS och inget JavaScript.

Jag har ändå använt sådant som HTML kan göra själv. Till exempel använder jag `details` och `summary` för GDPR och villkor, så den delen kan öppnas och stängas utan JavaScript.

Jag har också använt olika typer av formulärfält beroende på vad som ska skrivas in, till exempel `email`, `tel`, `search`, `checkbox`, `select`, `textarea` och `submit`.
